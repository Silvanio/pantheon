## Why

Five independent gaps reported in the same session: (1) there is no way for Pantheon's own operators to see across every tenant company — no platform-admin concept exists at all; (2) the four paginated obra listings (Diário de Obra, Equipamentos, Pedido de Compra, Orçamentos) have no way to change how many results load per page; (3) leaving a Diário de Obra/Pedido de Compra/Orçamento detail page always lands back on the obra's Resumo tab instead of the list the member came from, because `SiteDetailView`'s active tab is pure in-memory state, never reflected in the URL; (4) every native checkbox in the app renders with the browser's unstyled default look (worst in dark mode), inconsistent with the rest of the design system; (5) the company-wide Global Tasks Board has no way to narrow the aggregated view down to a single obra.

## What Changes

- **Platform superadmin**: a new `AppUser.superAdmin` flag, checked via a new `PlatformAdminService`, bypasses every company/site membership gate (`CompanyService`, `ConstructionSiteService`, `SiteAccessService`) — a superadmin is treated exactly like company staff everywhere without needing any membership row. A new `GET /api/admin/companies` endpoint lists every company platform-wide, paginated and searchable by name. A new `pantheon-web` route (`/admin`, `AdminCompaniesView.vue`) lets a superadmin filter companies via a dropdown-with-search popover (mirroring the Global Tasks Board's obra filter: up to 10 results, name search from 3 characters), then see the selected company's obras rendered as dashboard-style cards (photo, progress, status badge) and a link to its settings. The router's post-login guard sends a superadmin straight there instead of through normal company onboarding. The initial superadmin account (`inextitsolutions@gmail.com`) is seeded via a Flyway migration.
- **Page-size selector**: `DailyReportsPanel.vue`, `EquipmentPanel.vue`, `PurchaseRequestPanel.vue`, and `OrcamentoListPanel.vue` each gain a "Mostrar" dropdown (1/5/10 results per page) next to their existing prev/next pagination controls; changing it resets to page 0 and reloads. No backend changes were needed — the four existing paginated endpoints already accepted an arbitrary `size` query param.
- **Breadcrumb navigation**: `SiteDetailView.vue`'s active tab can now be seeded from a `?tab=` query param on mount (previously it always reset to `'summary'`). `DailyReportDetailView.vue`, `PurchaseRequestDetailView.vue`, and `OrcamentoDetailView.vue` each replace their "voltar" button with a new shared `SiteBreadcrumb.vue` component (`Obra Name / Section`), both crumbs being real links — the section crumb carries `?tab=<theTab>` so it lands back on the right tab instead of the Resumo default. Their post-delete redirects were updated the same way (no more `router.back()`).
- **Checkbox styling**: a new `.field-checkbox` utility class in `style.css` (border, rounded corners, `accent-color` in both themes, focus ring) replaces every ad hoc/unstyled `<input type="checkbox">` in the app (the item-selection checkboxes on the Pedido de Compra detail page, the Diário de Obra "weather blocked tasks" checkbox, and the Cronograma Gantt's task-done checkbox).
- **Breadcrumb moved into the page header, with a back-arrow icon**: `SiteBreadcrumb.vue` now renders inside `AppHeader`'s `#left` slot (not inline in the page body) on all three detail views, and gained a leading back-arrow icon-link that navigates to the same section target as the text crumb — a one-click "back" affordance in addition to the breadcrumb trail itself.
- **Global Tasks Board obra filter**: `GlobalTasksBoardView.vue` gains a searchable obra filter — a dropdown button (showing "Todas as obras" or the selected obra's name) that opens a popover with a search input and up to 10 matching obras; typing 3 or more characters filters the company's full obra list by a case-insensitive "contains" match, entirely client-side (the obra list was already being fetched in full for card rendering, and obra counts per company are modest, so no new paginated backend endpoint was needed). Selecting an obra filters every column's cards down to that obra; a "Limpar filtro" button resets to all obras.
- **Global Tasks Board card enrichment**: each card now shows the same summary detail as its per-obra counterpart — assignee initials (up to 3, with a "+N" overflow and name tooltips), an attachment indicator icon, and a comment-count icon, alongside the due date/labels/obra badge already shown. `GlobalTaskBoardService` now also aggregates `TaskCardAssignee`/comment/attachment counts across every site's cards in one pass (reusing the exact repository methods `TaskCardService.getBoard` already uses, just fed the full cross-site card-id list instead of one site's), and resolves each referenced assignee's display name company-wide (mirroring `SiteMembershipService.listMembers`'s AppUser-or-accountless-name fallback), returned as a new `assignees` list on the board response.
- **Superadmin gap fix**: while verifying the Global Tasks Board filter live, found that `GlobalTaskBoardService` had its own independent company-admin membership check (not routed through `CompanyService`) that the superadmin bypass had missed — added the same `PlatformAdminService` bypass there for consistency.

## Capabilities

### New Capabilities
- `platform-admin`: a superadmin role that bypasses company/site membership checks platform-wide, plus the cross-tenant company picker UI.

### Modified Capabilities
- `daily-construction-report`: adds a page-size selector to the report list, and a header breadcrumb with a back-arrow icon (replacing the back button) on the report detail view.
- `equipment-material-registry`: adds a page-size selector to the equipment list.
- `purchase-requests`: adds a page-size selector to the Pedido de Compra list, and a header breadcrumb with a back-arrow icon on its detail view.
- `orcamento-management`: adds a page-size selector to the Orçamento list, and a header breadcrumb with a back-arrow icon on its detail view.
- `obra-visual-design`: adds a standard checkbox appearance (`.field-checkbox`) to the design system's component classes.
- `global-tasks-board`: adds a searchable, capped-at-10 obra filter to the aggregated board, closes the superadmin-bypass gap in `GlobalTaskBoardService`, and enriches each card with assignees/attachment/comment indicators matching the per-obra board.

## Impact

- Backend: `AppUser` (+`superAdmin` column, migration `V60`), new `PlatformAdminService`/`NotSuperAdminException`, bypass checks added to `SiteAccessService`/`CompanyService`/`ConstructionSiteService`/`GlobalTaskBoardService`, new `PlatformAdminController` (`GET /api/admin/companies`), new `CompanyRepository.findByNameContainingIgnoreCase`, `JwtService`/`UserResponse` carry a `superAdmin` flag.
- Frontend: new `AdminCompaniesView.vue` + `/admin` route, router-guard changes in `router/index.ts`, `useAuth.ts` (`isSuperAdmin`), `useCompanies.ts` (`listAllCompanies`); page-size selectors in the four list panels; new `SiteBreadcrumb.vue` (rendered in each detail view's `AppHeader`, with a back-arrow icon) used by three detail views; `SiteDetailView.vue` reads `?tab=`; `.field-checkbox` in `style.css` applied at 4 call sites; `GlobalTasksBoardView.vue` gains the obra-filter dropdown (client-side, reusing the already-fetched obra list).
- No changes to `pantheon-mobile` — all five items are web-only (mobile's list screens already use a non-paginated flat-fetch pattern by design, and mobile has no global tasks board, detail-view back-button, or checkbox issues in scope here).
