## MODIFIED Requirements

### Requirement: Photo and video upload
`pantheon-service` SHALL allow a project member to upload one or more photos or videos against a daily report, stored as files in object storage (never as database rows) with an optional caption, SHALL allow updating a media entry's caption afterward, and SHALL allow removing a media entry while the report is still a draft.

#### Scenario: Photo uploaded
- **WHEN** a project member uploads a photo file to a daily report, optionally with a caption
- **THEN** `pantheon-service` stores the file in object storage under that report's key path and records a `DailyReportMedia` entry referencing it

#### Scenario: Media gallery listed
- **WHEN** a project member requests a daily report's media
- **THEN** `pantheon-service` returns every `DailyReportMedia` entry for that report, in upload order, including when it was uploaded

#### Scenario: Media content retrieved
- **WHEN** a project member requests a specific media entry's file content
- **THEN** `pantheon-service` returns the stored bytes with the original content type

#### Scenario: Media caption updated
- **WHEN** a project member updates a media entry's caption on a draft daily report
- **THEN** `pantheon-service` saves the new caption

#### Scenario: Media entry removed
- **WHEN** a project member removes a media entry from a draft daily report
- **THEN** `pantheon-service` deletes that entry and its stored file

### Requirement: Document attachments
`pantheon-service` SHALL allow a project member to upload one or more document attachments against a daily report, stored as files in object storage, and SHALL allow removing an attachment while the report is still a draft. It SHALL also surface, read-only, any Pedido de Compra invoice (`PurchaseRequestInvoice`) uploaded for the same construction site on the same calendar date as the report's `reportDate`, referencing its source Pedido de Compra, regardless of that Pedido de Compra's own date.

#### Scenario: Attachment uploaded
- **WHEN** a project member uploads a document file to a daily report
- **THEN** `pantheon-service` stores the file in object storage under that report's key path and records a `DailyReportAttachment` entry referencing it, its original filename, and when it was uploaded

#### Scenario: Attachments listed
- **WHEN** a project member requests a daily report's attachments
- **THEN** `pantheon-service` returns every `DailyReportAttachment` entry for that report

#### Scenario: Attachment content retrieved
- **WHEN** a project member requests a specific attachment's file content
- **THEN** `pantheon-service` returns the stored bytes with the original content type

#### Scenario: Attachment removed
- **WHEN** a project member removes an attachment from a draft daily report
- **THEN** `pantheon-service` deletes that entry and its stored file

#### Scenario: Same-day Pedido de Compra invoice surfaced
- **WHEN** a Pedido de Compra invoice for the report's construction site was uploaded on the same calendar date as the report's `reportDate`
- **THEN** `pantheon-service` includes it in that report's attachments view, referencing its source Pedido de Compra, without copying the file

#### Scenario: Invoice from a different upload date is not surfaced
- **WHEN** a Pedido de Compra invoice for the site was uploaded on a date other than the report's `reportDate`
- **THEN** `pantheon-service` does not include it in that report's attachments view, even if the Pedido de Compra itself references an earlier date

### Requirement: Media, attachment, and sign-off UI
`pantheon-web` SHALL provide, within the daily report view, a drag-and-drop-capable media gallery with upload and per-item caption editing, an attachment list with upload (including same-day Pedido de Compra invoices, visually marked as such), and a PDF download action, with all copy sourced from the `pt-BR` locale resource file. The sign-off action is **not** shown in this UI (the backend capability is unchanged and unused here — see `daily-report-approval-workflow` for the approval history that now closes the report instead).

#### Scenario: Member uploads a photo from the UI
- **WHEN** a project member selects a photo file and uploads it from a daily report's view
- **THEN** `pantheon-web` submits the file to `pantheon-service` and adds it to the report's media gallery

#### Scenario: Member drags photos onto the upload area
- **WHEN** a project member drags one or more photo or video files onto the media upload area
- **THEN** `pantheon-web` uploads each file the same way a click-to-browse selection would

#### Scenario: Member downloads the PDF from the UI
- **WHEN** a project member clicks the PDF download action on a daily report
- **THEN** `pantheon-web` downloads the PDF generated by `pantheon-service`

## REMOVED Requirements

### Requirement: Report sign-off UI is shown
**Reason**: The Diário de Obra now requires a multi-step approval workflow (see `daily-report-approval-workflow`) before it's considered final; the ad hoc sign-off list is redundant with, and predates, that mechanism. The backend `DailyReportSignature` capability itself is unchanged and still callable — only this UI surfacing is removed, since sign-off may return in a future change.
**Migration**: No action needed for existing data — past signatures remain stored and queryable; there is simply no UI entry point to view or create them in `pantheon-web` after this change.
