# daily-report-media-and-signoff Specification

## Purpose

Media (photos/videos), document attachments, member sign-off, and on-demand PDF export for a daily construction report — files live in S3-compatible object storage, never as database rows.

## Requirements

### Requirement: Photo and video upload
`pantheon-service` SHALL allow a project member to upload one or more photos or videos against a daily report, stored as files in object storage (never as database rows) with an optional caption.

#### Scenario: Photo uploaded
- **WHEN** a project member uploads a photo file to a daily report, optionally with a caption
- **THEN** `pantheon-service` stores the file in object storage under that report's key path and records a `DailyReportMedia` entry referencing it

#### Scenario: Media gallery listed
- **WHEN** a project member requests a daily report's media
- **THEN** `pantheon-service` returns every `DailyReportMedia` entry for that report, in upload order

#### Scenario: Media content retrieved
- **WHEN** a project member requests a specific media entry's file content
- **THEN** `pantheon-service` returns the stored bytes with the original content type

### Requirement: Document attachments
`pantheon-service` SHALL allow a project member to upload one or more document attachments against a daily report, stored as files in object storage.

#### Scenario: Attachment uploaded
- **WHEN** a project member uploads a document file to a daily report
- **THEN** `pantheon-service` stores the file in object storage under that report's key path and records a `DailyReportAttachment` entry referencing it and its original filename

#### Scenario: Attachments listed
- **WHEN** a project member requests a daily report's attachments
- **THEN** `pantheon-service` returns every `DailyReportAttachment` entry for that report

#### Scenario: Attachment content retrieved
- **WHEN** a project member requests a specific attachment's file content
- **THEN** `pantheon-service` returns the stored bytes with the original content type

### Requirement: Report sign-off
`pantheon-service` SHALL allow a project member to record their sign-off (`DailyReportSignature`) on a daily report only once that report has been submitted (`SUBMITTED`).

#### Scenario: Member signs a submitted report
- **WHEN** a project member submits a sign-off request for a daily report in `SUBMITTED` status
- **THEN** `pantheon-service` records a `DailyReportSignature` for that member on the report, including their construction function at the time of signing

#### Scenario: Cannot sign a draft report
- **WHEN** a project member attempts to sign a daily report that is still in `DRAFT` status
- **THEN** `pantheon-service` rejects the request

#### Scenario: Signatures listed
- **WHEN** a project member requests a daily report's signatures
- **THEN** `pantheon-service` returns every `DailyReportSignature` recorded for that report

### Requirement: PDF export
`pantheon-service` SHALL generate and return a PDF document of a daily report on request, including all of its sections, media, attachments, and signatures.

#### Scenario: PDF generated
- **WHEN** a project member requests the PDF export of a daily report
- **THEN** `pantheon-service` generates and returns a PDF reflecting that report's current sections, media, attachments, and signatures

### Requirement: Media, attachment, and sign-off UI
`pantheon-web` SHALL provide, within the daily report view, a media gallery with upload, an attachment list with upload, a sign-off action (enabled only once submitted), and a PDF download action, with all copy sourced from the `pt-BR` locale resource file.

#### Scenario: Member uploads a photo from the UI
- **WHEN** a project member selects a photo file and uploads it from a daily report's view
- **THEN** `pantheon-web` submits the file to `pantheon-service` and adds it to the report's media gallery

#### Scenario: Member signs a submitted report from the UI
- **WHEN** a project member clicks the sign-off action on a submitted daily report
- **THEN** `pantheon-web` submits the sign-off to `pantheon-service` and shows the member's name in the report's signature list

#### Scenario: Member downloads the PDF from the UI
- **WHEN** a project member clicks the PDF download action on a daily report
- **THEN** `pantheon-web` downloads the PDF generated by `pantheon-service`
